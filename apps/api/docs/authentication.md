## Токен доступа

Каждый запрос к защищённым эндпоинтам должен содержать заголовок:

```http
Authorization: Bearer <access_token>
```

Токен — это короткоживущий JWT, который выдаёт сервис аутентификации Sb0rka после входа. Platform API сам токены не выпускает — он только проверяет подпись и срок действия. Токен используется как **identity-токен**: из него берутся идентификатор пользователя (`sub`), сессия (`sid`), тип субъекта (`sk`) и идентификатор токена (`jti`).

Когда срок токена истекает, получите новый через сервис аутентификации (refresh-сессия). В консоли и CLI это происходит автоматически.

### Ограничения v0.1.0

- Поддерживаются только субъекты типа `user`.
- Делегированный доступ (acting-as) не поддерживается.
- Биллинг-субъект проекта всегда равен его владельцу.

## Живая сессия

Часть эндпоинтов помечена как требующая **живой сессии** — это все операции, изменяющие данные (создание, изменение, удаление, раскрытие секретов). Для них, помимо валидного токена, платформа проверяет, что сессия ещё активна и не отозвана.

Операции только на чтение требуют лишь валидного токена.

В [справочнике](reference) такие эндпоинты помечены пометкой **live session**.

## Роли и права

Доступ проверяется по членству в проекте. У каждого участника одна роль:

| Роль | Назначение |
| --- | --- |
| `owner` | полный контроль, включая удаление проекта, смену плана и управление владельцами |
| `admin` | управление ресурсами и участниками (кроме владельцев) |
| `editor` | создание и изменение ресурсов, без управления участниками |
| `viewer` | только чтение, включая раскрытие секретов |

### Матрица прав

Каждое действие API соответствует праву. Доступность по ролям:

| Действие | owner | admin | editor | viewer |
| --- | :---: | :---: | :---: | :---: |
| Просмотр проекта | ✅ | ✅ | ✅ | ✅ |
| Изменение метаданных проекта | ✅ | ✅ | ✅ | — |
| Удаление проекта | ✅ | — | — | — |
| Смена плана / биллинга | ✅ | — | — | — |
| Список участников | ✅ | ✅ | ✅ | ✅ |
| Добавление / изменение / удаление участников | ✅ | ✅ | — | — |
| Список и чтение баз данных | ✅ | ✅ | ✅ | ✅ |
| Создание базы данных | ✅ | ✅ | ✅ | — |
| Изменение метаданных базы | ✅ | ✅ | ✅ | — |
| Старт / стоп базы | ✅ | ✅ | ✅ | — |
| Удаление базы | ✅ | ✅ | — | — |
| Параметры подключения | ✅ | ✅ | ✅ | ✅ |
| Список и чтение секретов | ✅ | ✅ | ✅ | ✅ |
| Создание секрета / версии | ✅ | ✅ | ✅ | — |
| Изменение метаданных секрета | ✅ | ✅ | ✅ | — |
| Раскрытие секрета | ✅ | ✅ | ✅ | ✅ |
| Отключение версии секрета | ✅ | ✅ | — | — |
| Удаление секрета | ✅ | ✅ | — | — |
| Список тегов | ✅ | ✅ | ✅ | ✅ |
| Создание / изменение / удаление тегов | ✅ | ✅ | частично | — |
| Привязка тега к ресурсу | ✅ | ✅ | ✅ | — |
| Отвязка тега от ресурса | ✅ | ✅ | — | — |

> `editor` может создавать, изменять теги и привязывать их, но не удалять и не отвязывать.

### Бизнес-правила управления участниками

Поверх матрицы действуют дополнительные правила:

- Назначить или повысить участника до `owner` может только `owner`.
- `admin` не может изменять или удалять участников с ролью `owner` и не может выдавать роли уровня своей или выше.
- Нельзя разжаловать или удалить **последнего** `owner` проекта.

При отказе по доступу API возвращает `403`.
