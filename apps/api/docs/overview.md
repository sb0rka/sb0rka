Platform API — основной программный интерфейс Sb0rka. Через него создаются проекты, разворачиваются базы данных, хранятся секреты и управляется доступ команды. Веб-консоль и CLI `s0c` — это клиенты поверх этого же API.

## Базовый адрес

```
https://api.sb0rka.ru
```

Все пути в [справочнике](reference) указаны относительно этого адреса. Аутентификация описана в разделе [Аутентификация и доступ](authentication).

## Формат данных

- Запросы и ответы — JSON (`Content-Type: application/json`), кроме раскрытия URI базы данных, который возвращается как `text/plain`.
- Тела запросов проверяются строго: **неизвестные поля приводят к ошибке** `400 Bad Request`.
- Временные метки — в формате RFC 3339 (`2026-06-06T12:00:00Z`).

## Идентификаторы

| Идентификатор | Вид | Пример |
| --- | --- | --- |
| `project_id` | hex-строка | `a1b2c3d4e5` |
| `resource_id` | hex-строка (база данных или секрет) | `0f1e2d3c4b5a` |
| `subject_id` | UUID пользователя | `7c9e6679-7425-40de-944b-e07fc1f90ae7` |
| `version_no` | целое число версии секрета (≥ 1) | `3` |

Проект — это контейнер. Внутри проекта живут **ресурсы** двух видов: `database` и `secret`. У каждого ресурса есть собственный `resource_id`, уникальный в рамках проекта.

## Состояния ресурса

Sb0rka разделяет **желаемое** состояние (которое задаёте вы) и **фактическое** runtime-состояние (которое платформа приводит к желаемому).

Желаемое состояние базы данных (`desired_runtime_state`):

| Значение | Смысл |
| --- | --- |
| `running` | база должна работать |
| `suspended` | база должна быть приостановлена |
| `terminated` | база помечена на удаление |

Фактическое runtime-состояние (`resource_state.runtime_state`):

`syncing` · `creating` · `available` · `starting` · `stopping` · `stopped` · `deleting` · `deleted` · `failed`

После запроса на старт/стоп/удаление ресурс переходит в промежуточное состояние и достигает целевого асинхронно — опрашивайте `resource_state`, чтобы отследить результат.

## Ошибки

| Код | Когда возникает |
| --- | --- |
| `400` | некорректное тело запроса, невалидное имя/параметр |
| `401` | отсутствует или невалиден токен доступа |
| `403` | у роли нет права на действие, либо нарушен бизнес-инвариант |
| `404` | ресурс не найден |
| `409` | конфликт (дубликат, последний владелец, неактивная версия секрета) |
| `500` | внутренняя ошибка |

Большинство ошибок возвращается как текст с соответствующим HTTP-кодом; часть (например, отказ доступа) — как `{"error":"forbidden"}`.

## С чего начать

1. Получите токен доступа — см. [Аутентификация и доступ](authentication).
2. Инициализируйте аккаунт: `POST /account/initialize` (привязывает бесплатный план).
3. Создайте проект: `POST /projects`.
4. Разверните базу данных: `POST /projects/{project_id}/dbi`.
5. Получите строку подключения: `POST /projects/{project_id}/resources/{resource_id}/dbi/uri/direct/reveal`.

Полный список — в [Справочнике эндпоинтов](reference).
