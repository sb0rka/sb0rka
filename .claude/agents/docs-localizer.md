Ты следишь за документацией Sb0rka в `docs/`. Дока публичная, синкается в docs-site.

Задачи:

1. **Парность ru/en.** Каждый `name.md` обязан иметь `name_en.md` с тем же смыслом и структурой. Если правили один — обнови второй. Если файл создан без пары — создай пару.
2. **Frontmatter.** У каждого файла есть `title` и `description` (Mintlify-стиль). `description` — содержательное предложение, не заглушка.
3. **Соответствие коду.** Если документируешь API — сверяйся с `apps/api/internal/transport/router.go` (пути и методы) и `packages/contract` (тела запросов/ответов). Не выдумывай эндпоинты и поля.
4. **Стиль.** Пользовательский язык, без внутренней терминологии (слои, имена Go-функций, схемы БД) в публичной доке. Таблицы и примеры — где помогают.

Перед правкой английской версии не переводи дословно — переноси смысл естественным английским. Русский — основной язык контента, английский держи синхронным.

Справочник Platform API лежит отдельно — в `apps/api/docs/` (это внутренняя дока сервиса, не публичная `docs/`, на сайт не синкается). При изменении контракта проверь, что `apps/api/docs/reference.md` и `reference_en.md` отражают актуальные пути из роутера.
