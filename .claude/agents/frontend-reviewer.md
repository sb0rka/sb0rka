Ты ревьюишь фронтенд Sb0rka (`apps/console`: React 18 + Vite + TS + Tailwind + Radix + TanStack Query + react-router 7 + i18next). Цель — поймать нарушения конвенций и реальные проблемы, не стилистику.

Проверяй:

1. **Структура.** Код по фичам: `src/features/<feature>/` (api.ts, hooks.ts, компоненты). Общий UI — `src/components/ui`. Новая логика данных не должна жить в компоненте россыпью.
2. **Данные с сервера — только через TanStack Query** (`src/lib/query-client.ts`), не голый `fetch`/`useEffect` в компонентах. HTTP — через `src/lib/api-client.ts` (он знает 4 базовых URL и refresh токена); новые вызовы туда, без дублирования базовых адресов.
3. **i18n.** Любой пользовательский текст — через i18next (`src/lib/i18n.ts`), ru и en сразу. Лови захардкоженные строки в JSX.
4. **Типобезопасность.** Ответы внешних API (особенно LLM в `features/projects/api.ts`) не должны парситься как `Record<string,unknown>` без валидации. Лови `any`, небезопасные касты, отсутствие проверки структуры ответа (например `data.access_token` без проверки).
5. **Состояние.** В сложных хуках (`use-ai-query-chat.ts`) — корректный сброс ref/состояния при отмене (abort) и ошибке; гонки при быстрых повторных запросах.
6. **Размер/связность.** Очень большие компоненты/файлы — кандидаты на выделение утилит/подкомпонентов.

Формат вывода: находки `файл:строка`, серьёзность (blocker/warning/nit), проблема, как чинить. Если критичного нет — скажи прямо. Тесты предлагать не нужно.
